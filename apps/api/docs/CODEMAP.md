**Keep it current:** whoever adds, moves or deletes a file under `src/` updates its line here in the same change.

## Request pipeline (WhatsApp text message)
```
routes/whatsapp/webhook-whatsapp.ts       HMAC check → dedup (whatsapp_webhook_events) → lead/conversation → persist inbound → enqueueTask(process_inbound_message, debounce cutoff)
services/reliability/background-workers.ts → autonomous-task-executor.ts (claim with lease, one task per conversation)
services/conversations/autonomous-task-handlers.ts  handleProcessInboundMessage → batch (inbound-message-batch.ts) → generateMarianaResponse → enqueueOutboundMessage
services/conversations/generateMarianaResponse.ts   lead + history → conversation-stage.ts (stage/question) → ai/agent.ts (Gemini) → update-lead-from-agent → execute-next-action → persistAuthorizedAssistantReply → scheduling offer
services/messaging/outbound-messages.ts   outbox claim/lease → whatsapp-compliance → integrations/whatsapp/whatsapp-client.ts → sent/unknown/failed
```
Button replies: `webhook-whatsapp.ts` → task `process_button_reply` / `send_confirmation_request` → handlers in `autonomous-task-handlers.ts` → `services/calendar/*` → outbox. Legacy `pref:*` / `consultant:*` / `sessao:*` taps under 4h get the stale-tap reply in the webhook tx (no task).
Scheduling flow (R-SCH-01 v1.4, steps 30–31): offer → up to 3 slot buttons (session `awaiting_slot_selection`; a single slot is pre-selected, `awaiting_confirmation`) → slot tap → Confirmar/Não → booking. No consultant preference question; nothing enqueues `send_consultant_preference_question`. Step 32 (one release): pending legacy `send_consultant_preference_question` → no-op; pending `process_consultant_*` → stale-tap reply; slot tap accepted in the 3 legacy stages. Step 33: Confirmar on a slot taken meanwhile (`slot_unavailable`) → `sendSlotUnavailableReoffer` (fresh draw, new session via `persistOffer({ executor })`, D-R2-6 text, key `reoffer:<externalId>`, one tx; no slots → no-slot text, old session closed). Step 35: a single fresh slot → one line "Esse horário acabou de ficar indisponível. Tenho outro horário: <data hora> com <consultor>. Posso confirmar?" (`SLOT_UNAVAILABLE_SINGLE_REOFFER_PREFIX`) + Confirmar/Não. Step 34: any tap the stage refuses (old slot, old Confirmar/Não, expired/absent session; not `appointment_failed`, not `slot_unavailable`) → `replyToRefusedTap` (lead FOR UPDATE, conversation still `active`, then `replyToStaleTap`, key `stale-tap:<externalId>`).

## Tests
- Unit list (no DB): the explicit file list in `package.json` → `test:unit`. A new unit test file must be added there.
- DB tests: everything else under `src/tests/**` (`test:db`, local `TEST_DATABASE_URL`).
- Support: `src/tests/support/` (guards, preloads, `setup-test-db.ts`, seed). `test-network-egress-guard.ts`: both preloads block non-loopback network egress (`ALLOW_TEST_NETWORK=1` hatch). `lock-wait.ts`: DB lock tests wait for a real block (`pg_blocking_pids`), no sleeps; used by `src/tests/reliability/lock-order.test.ts`. `src/tests/test-env-isolation.test.ts` (unit): child processes with a fake `.env` prove `.env` never overrides the preloads' `DATABASE_URL` or fake credentials.
- Route table: `src/tests/support/route-table.ts` (`PUBLIC_ROUTES`, `ADMIN_ROUTES`); `routes/route-inventory.test.ts`, `routes/admin-auth.test.ts` and `routes/google-oauth.test.ts` (unit), `routes/admin-routes.test.ts` and `routes/google-oauth-db.test.ts` (DB).
- Folders: `src/tests/{services,reliability,routes,integrations,google-calendar}`.
- Simulator: `scripts/simulate-conversation.ts` (`npm run sim:conversation`; `--flow v2` mocked Gemini by default, v1 and real Gemini only with `--real-gemini` — owner permission only). Flags: `src/tests/support/simulation-args.ts`; v2 scenarios: `src/tests/support/conversation-simulator.ts` (`V2_SIMULATION_SCENARIOS`).
